# One repo: retire the private dev repo and the publish seam

Status: planned
Date: 2026-10-07

## Problem

Brainforge lives in two repos: a private dev repo and a public staging repo fed by `/publish`
through an allowlist, three hand-maintained `*.public.md` variants, a leak denylist, and a
PreToolUse tracker hook. The split exists only to keep client details out of public view. It has
cost a version lag (dev 0.13.2 vs public 0.13.1), a public roadmap four minor versions stale, two
CONTRIBUTING corollary rules enforced by convention, and recurring hook false positives.

## Decisions

| # | Decision | Made by |
|---|---|---|
| D1 | One repo. `jrpease/brainforge` (public, the marketplace source subscribers already use) is the home. | Jordan, 2026-10-07 |
| D2 | All client information used to build the plugin is removed — not scrubbed into variants, removed. It is no longer needed. | Jordan, 2026-10-07 |
| D3 | Session residue goes with it: `docs/handoffs/`, `docs/notes/`, `docs/superpowers/`, `EXTRACTION.md`. | follows from D2 |
| D4 | The publish seam is deleted: `/publish`, `publish-audit.json`, `scripts/tracker-audit.sh` + its hook, `*.public.md`, plugin.json `publish` block, the corollary rules that exist only for the seam. | follows from D1 |
| D5 | Specs and proofs keep their mechanism reasoning; client names become generic ("a subscriber brain", "the audited brain"); client data (store, analytics, board contents) is deleted. | follows from D2 |
| D6 | The dev repo is archived, not deleted. Its history (which holds client detail) never gets pushed to the public repo; the merged tree lands as one new commit on the public repo's existing history. | follows from D1/D2 |
| D7 | The no-em-dash rule for public docs (backlog spec D11) is dropped, along with `tests/public-docs.test.sh` and its CONTRIBUTING line. It existed to police the public variants; the merged docs use em dashes. | follows from D4 |

## Plan

1. On a dev-repo branch: delete D3/D4 paths, consolidate README/DESIGN/ROADMAP from the current
   private versions (the public variants are stale), scrub D5 files, drop tests for deleted machinery.
2. Gate: the old denylist patterns return zero hits across every tracked file; every remaining test passes.
3. Copy the tracked tree into the public clone on a branch, PR, merge.
4. Archive the private dev repo.
